# Image → Code (사진 한 장으로 화면 만들기)

세 가지 도구를 한 흐름으로 묶는다.

| 단계 | 도구 | 역할 |
|---|---|---|
| ① 눈 | 이미지 분석 (Claude 기본 기능) | 올린 사진에서 색·글꼴·배치를 뽑아낸다 |
| ② 감각 | `taste-skill` (design-taste-frontend) | AI 티 나는 뻔한 디자인을 걸러낸다 |
| ③ 확인 | Playwright (`.mcp.json`) 또는 `agent-browser` 스킬 | 브라우저로 직접 열어 스크린샷을 찍고 원본과 비교한다 |

## 1단계: 이미지 해부 (코드 쓰기 전에 먼저 적는다)

사진을 보고 아래 표를 채워 사용자에게 짧게 보여준다.

| 항목 | 뽑아낼 내용 |
|---|---|
| 색상 | 배경·본문 글자·강조색 HEX 코드 3~6개 |
| 글꼴 | 세리프/산세리프, 굵기, 제목과 본문 크기 비율 |
| 배치 | 섹션 순서, 칸 나눔(1단/2단/그리드), 여백 크기 |
| 모양 | 모서리 둥글기, 그림자, 선 두께 |
| 분위기 | 한 줄 요약 (예: "차분한 고급 에디토리얼") |

## 2단계: taste-skill 적용

`taste-skill` 을 불러와 브리프 추론·금지 패턴·사전 점검 규칙을 따른다.
사진에서 뽑은 값이 기준이고, taste-skill 은 빈 곳을 채우고 뻔한 AI 스타일을 막는 데 쓴다.

## 3단계: 코드 작성

- 기본은 HTML 파일 하나 (CSS·JS 포함). 사용자가 React 등을 원하면 그에 맞춘다.
- 사진 속 글자는 그대로 쓰되, 사용자가 내용을 주면 그 내용으로 바꾼다.
- 사진 속 이미지 자리는 비슷한 비율의 자리표시(단색 박스나 그라데이션)로 둔다.
- 휴대폰 화면(약 400px)에서도 깨지지 않게 만든다.

## 4단계: 브라우저로 직접 확인 (생략 금지)

1. Playwright 도구(`browser_navigate`, `browser_take_screenshot`)가 있으면 그걸 쓰고, 없으면 `agent-browser` 스킬을 쓴다.
2. 만든 파일을 열어 데스크톱(1440px)과 휴대폰(390px) 두 크기로 스크린샷을 찍는다.
3. 원본 사진과 나란히 비교해 차이 3가지를 찾아 고친다.
4. 2~3회 반복해 충분히 비슷해지면 끝낸다.

## 5단계: 전달

- 완성 파일 경로와 스크린샷을 보여준다.
- "원본과 달라진 점"을 한 줄씩 적는다 (예: 저작권 있는 로고는 뺐음).

## 주의

- 다른 회사 로고·상표·사진은 그대로 베끼지 말고 느낌만 가져온다.
- 사진이 흐리면 추측한 값임을 밝힌다.
